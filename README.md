# AI Test Runner

## 全局 AI 助手

右下角的助手入口在各页面均可使用，沿用“设置 / 模型设置”的配置。对话按产品隔离并持久保存在 `.data/assistant.json`；切换页面不会丢失对话，历史对话可从面板中选择。

助手不读取源码或修改代码。它可操作当前产品的平台业务数据，也可按用户明确要求调用当前产品设备资源中的 SSH、Telnet、串口和 API 控制接口。工具调用只传设备和接口 ID，连接目标及凭据由平台内部解析，凭据不会提供给模型；跨产品设备不会注册为本轮工具。设备调用立即执行并在助手面板中显示结果，不经过资产变更确认。用例、场景、设备、测试单编辑窗口会提供当前未保存的草稿；模型提出草稿变更后，通过“应用到表单”填入，仍需手动保存。草稿已修改或关闭时不会应用旧预览。

| 通用工具 | 作用 |
| --- | --- |
| `platform_context` | 读取当前产品、页面、草稿和字段定义 |
| `platform_query` | 按名称、ID、场景/测试单/设备关联关系查询资产，支持分页 |
| `platform_get` | 读取设备、场景、用例、测试单详情，设备密码不返回 |
| `platform_propose_changes` | 提出新增、部分修改、删除及关联关系变更，单次最多 200 项 |
| `platform_propose_draft` | 提出当前表单的部分字段修改 |

设备控制复用下方的 `device_ssh_exec`、`device_telnet_exec`、`device_serial_exec` 和 `device_http_request`。助手必须先查询当前产品设备及接口 ID；只在用户明确要求设备操作时调用。查询与诊断默认采用只读命令，用户明确要求配置时允许写操作。重启、恢复出厂、清空配置或断网等高影响操作在目标或影响不明确时应先询问。

资产变更统一展示差异和关联影响，确认后原子保存；任一操作校验失败则整批不保存。确认前产品资产若已变化，需要重新生成预览。新增和关联任务可由助手组合通用工具分阶段完成，没有特定场景的专用工具。历史执行快照不受资产修改影响。用例诊断助手仍作为独立入口保留。

## 设备控制工具

测试场景的设备角色由“角色标识”和“绑定设备”组成，例如 `DUT → TAU1`、`src → PC1`。同一场景内不能重复绑定设备，不同场景可以使用同一设备。平台只会向 Agent 注册当前场景绑定设备上实际可用的控制工具，模型不再自主选择设备或重新分配角色。模型调用工具时使用设备 ID 和控制接口 ID，地址及凭据由服务端从设备资源中读取。

测试单包含有序用例集合。编辑测试单时可以分别调整场景组顺序和每个场景内的用例顺序；执行时依次处理场景组，在每组用例前执行场景搭建和验证，再按组内顺序执行用例，结束后按配置执行清理。默认场景可编辑设备绑定，但不执行额外搭建。新执行记录及报告按真实执行顺序保存场景定义、固定角色绑定和用例快照。

旧版目录数据升级至版本 11 时会在同目录保留 `catalog.json.v旧版本号.bak` 备份，旧物理环境的连接说明会迁入关联场景的说明。旧角色不会自动猜测绑定设备，需要在场景编辑中选择设备后才能执行。物理环境不再作为独立实体或测试单参数。

| 控制接口类型 | Agent 工具 | 地址格式 |
| --- | --- | --- |
| SSH | `device_ssh_exec` | `192.168.1.1:22` 或 `ssh://192.168.1.1:22` |
| Telnet | `device_telnet_exec` | `192.168.1.1:23` 或 `telnet://192.168.1.1:23` |
| 串口 | `device_serial_exec` | `/dev/ttyUSB0?baudRate=115200&dataBits=8&stopBits=1&parity=none` |
| API | `device_http_request` | `http://192.168.1.1/api/` |

SSH 需要配置账号，密码可以留空。Telnet 会使用已配置的账号密码完成登录。API 同时配置账号和密码时使用 Basic Auth；只配置密码时将密码作为 Bearer Token。串口当前支持服务端本机可访问的串口路径，默认参数为 `115200/8N1`。

设备工具返回真实输出后会记录一次执行证据，因此纯 SSH、Telnet、串口或 API 用例也可以通过 `finish_test` 提交通过结论。连接失败或操作被取消时不会记录执行证据。

Telnet 在一次 Agent 会话内复用连接、保留 CLI 配置视图，同一接口的请求串行执行，多行命令逐条等待提示符。支持 Linux Shell 及华为/H3C 风格提示符和分页输出；明确的 CLI 错误会停止本批后续命令。超时或断线不自动重发，后续调用的 `sessionReset` 表示需要重新确认视图。不同场景搭建、用例、清理会话之间不共享连接。串口同一接口的请求也会排队；`input` 留空时，`appendNewline=true` 发送回车，`false` 仅读取。

## 执行收尾与排障

场景搭建、测试用例和清理使用不同的执行指令。用例阶段必须遵守指定操作路径，例如 Web 配置不能用底层 CLI 写操作替代；预期不符时收集证据并提交失败，不得擅自修复被测功能后宣称通过。此限制是模型提示词约束，不是命令级强制拦截。

模型正常结束却未调用 `finish_test` 时，平台只补交一次结论：关闭设备和浏览器工具，仅保留 `finish_test`，不得重新执行设备操作。补交仍未提交结论、上下文压缩失败等情况明确记录为“执行异常”；报告中用例的执行失败与正常完成后的断言不通过可通过状态和摘要区分。

长执行每 30 秒记录一次处理进度；若模型或工具连续 5 分钟没有真实事件，仍会触发超时，进度提示不重置超时。上下文压缩临时关闭推理，结束后恢复原设置；模型停止原因、用量、上下文使用、压缩/重试结果保存在执行 JSONL 的 `agent_info` 事件中。

执行时间线的工具步骤可展开查看保存的工具输出，新记录最多保存 80,000 字符，并隐藏配置中的设备密码和模型 API Key。工具本身的输出上限仍然生效，旧历史没有保存完整输出时不能补回。

## 禅道用例导入

在“设置 / 禅道设置”中配置禅道地址、账号和密码。平台固定使用 REST API v1 路径 `/api.php/v1`，运行时自动获取 Token，并在认证失效后重新登录一次。

产品需要填写有效的禅道产品 ID 才能导入用例。用例库支持从禅道产品用例库或指定禅道测试单选择用例；平台使用禅道用例 ID 判断重复，默认跳过已经导入的用例。勾选“覆盖已导入用例”后会更新名称、前置条件、步骤和预期结果，但始终保留平台中设置的测试场景。

## 本地运行

需要 Node.js 22.19.0 或更高版本。

```bash
npm install
npm run dev
```

`npm install` 会检查并将与 `playwright-core` 版本匹配的 Chromium 下载到项目的 `.runtime/ms-playwright` 目录；该目录不提交到 Git。服务启动时还会主动检查浏览器能否实际启动，缺失时自动补装。浏览器检查或下载失败不会阻止 API 和非网页设备工具启动，具体状态与错误可从 `GET /api/health` 的 `browser` 字段查看；第一次网页操作也会再次尝试恢复。

如需使用系统中已有的 Chrome/Chromium，可通过 `CHROME_PATH=/完整/可执行文件路径` 指定。路径不存在时平台会回退到项目 Chromium。可用 `PLAYWRIGHT_BROWSERS_PATH` 修改项目浏览器保存位置，也可运行 `npm run browser:install` 手动检查/安装。只有在明确不希望安装浏览器时才设置 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`；此时若没有可用浏览器，网页测试会明确失败。

Chromium 本体由项目管理，但 Linux 的字体、图形和 NSS 等动态库仍属于操作系统。若健康检查提示缺少系统库，请由部署管理员执行 `npx playwright-core install-deps chromium`（可能需要 root 权限）；平台不会自行修改系统软件包。

浏览器工具包含打开、读取、点击、填写、下拉选择、拖拽、按键、等待和截图。`browser_drag` 接收来源元素和目标元素，二者都可以使用页面读取结果中的 `@eN` 引用或 CSS 选择器；拖拽完成后会返回新的页面状态供模型核验。
